# 文件与交付

## 目录与版本

每品只有一份工作目录，原始资料保留；成品分 `output/square/`、`vertical/`、`details/`、`basic/`，直出源图保存在 `output/originals/`，待明确淘汰后才归档旧版。

文件名建议 `square01-product-a-20261101-v1.png`；用途编号在前、稳定简称、日期、版本递增，单个文件名含扩展名不超过46字符是本流程的内部规范。不要表情、换行和系统禁用字符。不要仅改后缀伪装格式，不覆盖旧图。delivery.json 明确当前版本，不凭最新修改时间或最大版本号猜。

## 尺寸与格式

| 类型 | 画幅/目标文件规格 | 额外要求 |
|---|---|---|
| 5张方主图 | 1:1，实际像素按使用渠道确定 | 带已确认文案与适用水印 |
| 5张竖主图 | 2:3，实际像素按使用渠道确定 | 重新构图，不直接裁方图 |
| 常规详情 | 2:3，实际像素按使用渠道确定 | 按方案编号和顺序 |
| 真实报告增补页 | 原报告比例，完整内容 | 不强套2:3，不交模型重画 |
| 白底 | 800×800，PNG/JPG，约72dpi，小于3MB | 保护商品外纯白；优先一个完整包装主体 |
| 透明 | 800×800，PNG，约72dpi，小于3MB | 真透明像素与不透明商品都存在 |
| 场景方图 | 800×800，PNG/JPG，约72dpi | 无新增文案/水印，非白底 |
| 场景长图 | 800×1200，JPG，小于3MB | 自然纵构图，不拉伸方图 |

基础素材四类来自原制作流程采用的渠道规范快照，是本教程默认交付目标；**不宣称适用于所有平台或当前所有类目**。上传前另查目标渠道实际要求。

## 允许的技术适配

在使用者授权范围内：等比调整规定尺寸、编码及分辨率元数据；白底仅清理可靠保护区外近白背景；场景方图与长图等比适配目标尺寸。保留原图、另存版本、核源目标校验值。不拉伸、不裁掉商品、不改包装、不叠字；画幅不支持且没有已确认留白方案时暂停该素材。

本仓库脚本**只核验，不自动修图**。白底脚本只检查四周边缘，不会自动认出商品保护区；边缘纯白不等于保护区外全部纯白，需要另做可靠保护区核对。透明通道存在不等于边缘干净或主体完整；场景是否自然、包装是否失真必须实际看图。

## 交付清单

delivery.json 的 `images` 每行是一个当前图位，含 role、path、status；详情使用 order。`status` 为 generated/file_verified/reviewed/adopted 之一，仅表达有证据的阶段。不能用文件核验脚本自动推到 reviewed 或 adopted。

角色：square01—05，vertical01—05，basic_white、basic_transparent、basic_scene、basic_scene_long；常规详情 role 为 detail01、detail02…，type 为 detail；真实报告页 type 为 report；自有介绍页 type 为 introduction。详情序号 order 必须连续且唯一；最后一页 type 为 disclaimer。

`plan.detail_count` 写详情实际页数（含报告、介绍与末屏），`plan.include_introduction` 明确是否有自有可信介绍页。报告多页逐页登记，各占一页；不会吞掉常规说明页。未生成图位不填进 images，缺项写 progress.md。

## 预览

按清单只显示当前版本。详情单列同宽、保留原比例，不额外插标题、间隙或说明，点击开原图；其余图片分组展示。页首保留状态、张数与问题；来源、提示词、核验记录放序列外。核验失败如实保留，预览可看不等于验收通过。
