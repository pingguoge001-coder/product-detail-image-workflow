# 批量与恢复

## 分工

一个主控管任务清单，每品一个独立对话/执行单元，同时最多3品生产，超过就排队。这个数量是保守操作默认值，不是平台能力保证；还要服从当前宿主、账号额度与使用者约束。

共享总清单由主控唯一维护；执行方只写自己的产品目录，回报本品结果。共享浏览器或服务也必须有唯一操作方。每品内部按图位逐张生成，不并发轰炸生图接口。

派发时写清：产品稳定编号、真实输入位置、可写目录、当前阶段、可用参考、确认方式、交付物、核验要求、预算与停止点。实际完成前不把“已派发”写成“已完成”。

## 总清单字段

产品编号｜目录｜负责单元｜待派发/执行中/待查看/修订中/部分完成/完成/暂停｜当前版本｜实交张数｜证据入口｜缺项｜下一步｜更新时间。

收到回报先记待核验，再检查实际文件和清单。状态与事实分别写：首批生成完成但透明不合格，应记“首批已保存，文件部分未通过”。不能把未核实填成0或成功。

## 中断恢复

先读总清单、本品 progress.md、delivery.json、当前提示词与生成回执。逐一核当前文件路径和图位；已有且对应版本明确的先保留，从缺少的位置继续。工具结果未知先核原请求及输出，不换编号、换窗口重复提交。

单图失败先查原因、保留错误；相同办法连续两次无进展就停该图并报告，不自动换生图服务或无限重试。预算达到使用者阈值时停新任务、保存当前进度，不擅自购买额度。

## 停止点

方案待确认、首批待确认、整套待查看各按这次授权执行。用户说“先只做首批”就到首批停止。批量授权不自动扩大到发布、平台写回、发消息、付款、删除或整个资料库追溯返工。

模板：使用 prompts/02-批量主控.md。涉及自有业务系统时另加明确的单品连接与权限说明，不共享账号令牌。
