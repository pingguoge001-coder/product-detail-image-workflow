# 产品详情批量生图工作流

先核实资料，逐屏规划；先看一批，确认再展开；逐张保存，按文件验收；把返工变成下次的规则。

这是一份从实际食品、生鲜商品制作流程中抽取的**匿名通用版**：包含操作规则、输入模板、开工指令、案例方法和本地辅助工具。示例不包含真实商品照片、人物素材或经营数据；不承诺一次生成即满意，也不代表经过销售转化验证。

## 第一次用，照这五步

1. 把仓库下载为 ZIP 并解压，或克隆到本机。用能访问该文件夹的 AI 助手打开它，先读 `AGENTS.md`。
2. 复制 `config.example.json` 为 `config.local.json`，填写自己的品牌、确认方式及已确认的店铺政策；没有的信息保持空白。默认每批明确确认，超时不自动通过。
3. 复制 `templates/product/` 到仓库外自己的商品工作目录；或运行下面的新建命令。填好 `facts.md`，放入自己有权使用的真实图片。
4. 把 [单品开工指令](prompts/01-单品开工.md)发给助手，指定商品目录。先看展示方案，再做首批9张，确认后做剩余图片。
5. 文件核验并查看整套预览，记录问题；第一款跑通后，再按 [批量指令](prompts/02-批量主控.md)每次最多3个产品推进。

## 工具准备

- 一个能够读取本地资料、查看参考图、调用生图工具并把结果保存到本地的 AI 助手。原方法使用 Codex 的直连生图能力；其他环境需要按自身工具调整调用方式。
- 当前宿主提供的生图能力和相应账户额度。**本仓库没有生图接口封装，不会自动产生图片，也不包含账号或密钥。**应先确认自己的环境能完成一张参考图生成与本地保存；具体模型、价格和限制以所用服务当前说明为准。
- 以下辅助脚本使用 Python 3.10 或更新版本；图片核验与预览脚本还需 Pillow。已有环境可直接复用，新安装由使用者自行决定。

```sh
python -m pip install -r requirements.txt
python tools/new_product.py --root ../my-products --slug product-a --name 商品A
```

生成后填 `delivery.json`，再运行：

```sh
python tools/verify_delivery.py ../my-products/product-a --phase first
python tools/build_preview.py ../my-products/product-a
# 后续整套完成后：
python tools/verify_delivery.py ../my-products/product-a --phase full
```

核验结果默认只打印；重定向到自己的工作目录即可保存。预览始终标注为“待查看”，文件通过不代表商品事实、包装保真、文字正确、本人采用或平台通过。

## 三条必须理解的边界

- **风格可以借，商品事实不能借。** 包装、配料、规格、认证、保存和售后必须来自当前产品或自己的店铺政策。
- **自动继续需要提前明确授权。** 可选择“展示后实际等待30秒，无回复按推荐继续”，但缺包装、关键事实冲突、结果未知不适用；不等于已亲自看过。
- **成图与上线分开。** 这套流程到本地交付停止；上传、发布包、上架、发消息、付款和删除需要各自明确指令。

初次使用建议明确确认方案和首批；认可自己的第一款后再扩大批量。满意案例可以沉淀成参考，但不能把视觉认可写成销售效果已验证。
